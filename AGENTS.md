# git-judge-jev

GitHub Action that ranks PR hunks by how much human attention they deserve and flags where the PR's story does not match its diff.
`prd.md` is the spec.
Read it before changing behaviour, and change it in the same commit when a decision changes.

## Layout

| Path | What it is |
|---|---|
| `src/diff.ts` | Unified diff in, hunk records out. Pre-classifies lockfile, generated, vendored by path only |
| `src/questions.ts` | Every question asked of Jev. The one file a non-engineer is expected to edit |
| `src/judge.ts` | Sends hunks to TypeSafe. Owns the state cap, truncation, concurrency, per-hunk failure tolerance, the fake-client seam. Generated and vendored hunks get the gate questions only |
| `src/policy.ts` | Policy file schema, and the pure function from answers to findings |
| `src/context.ts` | Pure. The enclosing block of a hunk by indentation, and the other hunks that change the same identifiers. What the writer reads beside a flagged hunk |
| `src/writer.ts` | Generator interface, one verdict per flag with a materiality call, the TL;DR. Drops rejected warnings, never a gate. A writer outage leaves gates standing |
| `src/generators.ts` | OpenAI and Anthropic adapters behind the generator interface. No unit tests |
| `src/report.ts` | Pure rendering: the one summary comment, a part for people in prose and a collapsed block for coding agents in JSON, and the check. Reads the previous comment back for new/standing marks and dismissals. Snapshot-tested |
| `src/pipeline.ts` | Diff in, report out, through injected clients. The end-to-end test runs this |
| `src/github.ts` | Octokit adapter. No unit tests |
| `src/action.ts` | The GitHub Action. Reads inputs and the event |
| `src/cli.ts` | The same pipeline from a terminal, before the PR exists. Reads the environment and git |
| `src/entry.ts` | What `dist/index.cjs` is built from. Picks the action inside a workflow run with no arguments, the command line otherwise |
| `scripts/eval.ts` | `npm run eval`. Replays `eval/cases/` through the real pipeline with cached model answers and scores the report. `eval-score.ts` is the pure, unit-tested part |
| `scripts/corpus.ts` | `npm run corpus -- owner/repo`. Builds eval cases from merged PRs through `gh`, labelled from review comments and later fix commits, into `eval/corpus/` (ignored by git, it is other repos' code). Calls no model |
| `eval/cases/` | Labelled diffs. `pr.diff` comes from real `git diff`, `case.json` names must-read hunks and true flags by file and a string in the diff |
| `eval/results/` | Saved eval runs, committed. Compare before and after when a question, weight, or threshold changes |
| `scripts/try.ts` | `npm run try -- file.diff`. Runs the real pipeline locally with keys from `.env`, posts nothing |
| `dist/index.cjs` | Generated by `npm run build`. Never hand-edit. Commit it with every `src/` change |
| `test/fixtures/` | Diffs produced by real `git diff`. Regenerate with git, do not hand-write |

## Rules

- 2-space indentation, ES modules, relative imports end in `.js`.
- Only `action`, `cli`, and `scripts/` may read the environment. Every other module takes its inputs as arguments.
- No test may need an API key or the network. Fake the client, or pass a fake `fetch` to the real SDK.
- Test a stage through its public interface and assert on its output, never on the calls made on the way. `judge` is the exception, its requests are its output.
- Cross-question logic lives in `policy.ts`, never in the wording of a question.
- Only the ids in `GATES` can fail the check. Custom questions can never gate.
- Code questions never see the PR description. Classification never reads hunk content. Both are author-controlled.
- One comment per PR, updated in place, holding the complete report. No inline review comments, ever: each push would add a review and a notification per comment.
- The policy file is read from the base commit, never the PR head.
- A suspected secret is never sent to the generator, as a hunk or inside another hunk's context. It has already gone to one vendor.
- A path never spares a hunk the gates. Only a lockfile, named by exact basename, and a path the base policy lists under `exclude.unchecked` reach no model.
- A gate needs nothing but Jev. No writer outage, dismissal, or materiality call can clear one.
- The block for coding agents is a channel of instructions built from author-controlled code. Its only instructions are `action` and `resolvedWhen`, from the fixed tables in `report.ts`. Model text goes in as data, never as an instruction, and a gate is always `human_only`.
- The comment is the only state. Memory across pushes is read back from the previous comment, never stored elsewhere.
- Code questions and gates never see the PR description, in Jev or in the writer. The writer shows it only to the two claims about the PR's story: `unrelated_to_description` and `refactor_changes_behaviour`.
- After an intended change to the rendered comment, update snapshots with `npx vitest run -u` and read the diff.
- Do not call the TypeSafe API from memory. The reference is https://docs.typesafe.ai/llms.txt and the types in `node_modules/@typesafe-ai/sdk`.

## Commands

`npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
The first three must pass before a change is done, and `dist/` must be rebuilt.

## Conventions
- Use best practice branch prefixes.
- Never commit secrets. Keys live in ~/.ssh, recovery codes in _private/ at the workspace root, which you never open.
- Never hand-edit CHANGELOG.md or generated files.
- Do not add an agent name as commit co-author.
